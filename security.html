Security Standards & Protections

Multi-layered cryptographic protection, offline database isolation, and Google Cloud Firestore server-side scoping.

🛡️

1. Multi-Layer Security Architecture

UdharGuru is architected with defense-in-depth principles. Every customer debit/credit entry, calculation, and invoice voucher is protected from unauthorized access across both physical device storage and remote network transmission.

🔐 Zero Data Exposure: No unauthenticated client can read or modify your financial ledgers.
🔑

2. Authentication & Server-Side Scoping

Identity management is decoupled and hardened using world-class Google identity technologies:

  • OAuth 2.0 & Firebase Auth: Industry-standard cryptographic tokens ensure secure session validation with zero plain-text password storage.
  • Granular Firestore Security Rules: All cloud database queries are strictly enforced by server-side rules (request.auth.uid == ownerUid). No user can query or access records belonging to another merchant.
  • Biometric Device Lock: Native hardware-backed Fingerprint, Face Unlock, and secure 4-digit PIN locks protect against unauthorized access if your phone is borrowed or unattended.
☁️

3. Cloud Storage & Cryptographic Standards

Data integrity is maintained using top-tier cryptographic protocols:

  • In-Transit Encryption: All client-to-cloud communications are encrypted using Transport Layer Security (TLS 1.3) protocols.
  • At-Rest Encryption: Cloud backups stored on Google Cloud Firestore are encrypted at rest using AES-256 standard encryption keys.
  • Isolated Hive Local Storage: Offline data is stored in high-performance binary Hive boxes isolated within the Android application sandbox.
⚖️

4. Infrastructure Disclaimer & User Backup Responsibility

While UdharGuru operates on enterprise Google Cloud architecture, UdharGuru, Guruji Tech Point, and its developer team provide no absolute warranty against third-party server outages, cloud infrastructure corruption, or device-level loss.

  • Third-party cloud downtime, API deprecation, or internet service provider disruptions.
  • Accidental device damage, water damage, OS flashing, or local storage clearing.
💡 Merchant Backup Best Practice: We strongly encourage all merchants to export an offline JSON ledger backup periodically via Settings → Backup & Data → Export JSON Backup to ensure independent ledger redundancy.
